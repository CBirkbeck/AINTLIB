| `EllipticCurve/ProjectiveSpaceTwist.lean:2231` | `coordinateHyperplaneDualPairing_frameSection` | :2294 |

Why now: the rc1→rc2 delta is fifteen commits, every one a kernel change. The relevant one is
**#14806 "fix: make kernel `is_def_eq` caching order-independent"**: the kernel used to cache
successful defeq queries in a union-find (`equiv_manager`) that implicitly computed the *transitive
closure* — `is_def_eq(v0,v2)` could succeed from the cache after `is_def_eq(v0,v1)` and
`is_def_eq(v1,v2)`. Because the kernel's `is_def_eq` is sound but incomplete (not transitive), this
made answers order-dependent and let malformed recursors derive `False`; the fix replaces it with a
plain per-pair cache. The price is that proofs whose kernel check leaned on those transitive hits now
recompute the defeqs. The eight declarations above are exactly the `rfl` / `convert … using 1` /
`Iso.ext; rfl` / `change` obligations on `Scheme.GlueData`, `SheafOfModules.overUnitScalarEnd`,
`pullbackUnitIso`, `restrictOpenTrivialization` structures — deep instance/structure unfolding that
now exceeds the default 200000 heartbeats inside the kernel (the kernel limit is `maxHeartbeats`).
The other rc2 commits (#14807/#14843 `is_prop` requires a sort, #14808 type-check generated
recursors, #14849 bound kernel `Nat` numerals, #14582 datatype uniformity) do not match the symptom.

Evidence this is bump fallout, not pre-existing red: (i) sibling worktrees at the same base commit
`340875adf` on the rc1 pin hold oleans for `ProjectiveSpaceTwist` and `InvertibleSheafGlueData`
dated 2026-08-22; (ii) none of the four files sets `maxHeartbeats`; (iii) the mathlib range has no
AlgebraicGeometry / CategoryTheory content changes (only #42160, 2-torsion polynomial roots, and
file splits that keep re-export shims), and mathlib's own toolchain bump `85e3a25e00 (#43012)`
touched only `lake-manifest.json` + `lean-toolchain` — mathlib needed no adaptation, so this shows
up only in downstream proofs with kernel-heavy defeqs.

Fix: per-declaration `set_option maxHeartbeats N in`, `N` taken from kernel-profiling runs
(`bump-diag-<File>.out`: file-wide `maxHeartbeats 4000000` + `profiler true`, threshold 3 s).
Statements untouched. Follow-up for `/buzz`: restructure the defeq-heavy steps so the limits can
come back down.
