## Statement (Phase 1)

`PadicLFunctions.Coleman.cycloUnits p n` is **a definition** of the following.

Let `p` be a prime and `n : ℕ`. Inside the field `ℂ_[p]` of `p`-adic complex
numbers, let `ξ = ξ_{p^n} = zetaSys p n` be the fixed primitive `p^n`-th root of
unity, and let `F_n = ℚ(μ_{p^n}) = ℚ(ξ)` (the number field `Fglobal p n`). The
**cyclotomic units `𝒟_n` of `F_n`** are defined as the intersection of the global
unit group `𝒱_n = O_{F_n}^×` (`globalUnits p n`) with the multiplicative subgroup
of `ℂ_[p]ˣ` *generated by* the set `{±ξ} ∪ {ξ^a − 1 : 1 ≤ a ≤ p^n − 1}`
(`cycloGenSet p n`). In symbols, `𝒟_n = ⟨±ξ, ξ^a − 1⟩ ∩ O_{F_n}^×`. This is the
standard Washington/Iwasawa-theory definition of the cyclotomic-unit group at
prime-power conductor; the quotients `(ξ^a − 1)/(ξ − 1)` (the actual *units*, since
the bare `ξ^a − 1` are non-units at prime-power level) arise *inside* the
generated subgroup — the file proves exactly this in `cyclo_elems_mem_cycloUnits`
(the Coleman input `c_n(a) = (ξ^a−1)/(ξ−1)` is the word `num · den⁻¹`).

Variables / typeclasses involved (Lean side):
- `p : ℕ`, `[hp : Fact p.Prime]` — the prime (fixed at file scope).
- `n : ℕ` — the cyclotomic level (field `ℚ(μ_{p^n})`).
- ambient: `ℂ_[p] = PadicComplex p` (normed, algebraically closed, complete valued field).

Hypotheses (Lean side): none beyond the typeclasses — a plain `def`.

Conclusion (math): `cycloUnits p n = 𝒟_n`, the group of cyclotomic units of `F_n`.

Conclusion (Lean): `Subgroup ℂ_[p]ˣ` — n/a (definition, not a proposition).

Dependencies (both project-local, in the same file):
- `cycloGenSet p n : Set ℂ_[p]ˣ` (line 174) — the generating set `{±ξ} ∪ {ξ^a−1}`.
- `globalUnits p n : Subgroup ℂ_[p]ˣ` (line 106) — `O_{F_n}^×`, **already assessed**: verdict `NO-mathlib-has-it` (mathlib has `(𝓞 K)ˣ`); see `globalUnits.md`.

### Literature summary (Phase 3)

Concept identified as: **the group of cyclotomic units (circular units) `𝒟_n`
(Washington: `C_n`) of a cyclotomic field**, here at prime-power conductor
`F_n = ℚ(μ_{p^n})`, realised inside `ℂ_[p]`.

Sources agree on the standard form: **yes**, and unusually precisely. Washington
Ch. 8 / PlanetMath: `C_n` = (full unit group) ∩ (subgroup generated by the
cyclotomic numbers). Wikipedia (prime-power case): the group is generated by
`±ξ` and `(ξ^a − 1)/(ξ − 1)`. The project's
`cycloUnits = Subgroup.closure (cycloGenSet) ⊓ globalUnits` is a **literal
transcription** of the intersection-with-generated-subgroup definition; the
generating set `cycloGenSet = {±ξ} ∪ {ξ^a − 1}` matches the literature's
generators (the quotients `(ξ^a−1)/(ξ−1)` live *in* the closure, as the file's
`cyclo_elems_mem_cycloUnits` proof exhibits).

Most general standard form: the cyclotomic-unit group `C_n` of `ℚ(ζ_n)` for **any**
conductor `n` (not just prime powers), stated **abstractly** as a subgroup of
`O_{ℚ(ζ_n)}^×` (no completion / no embedding in `ℂ_p`). For composite `n` the
generators differ (`ζ_n^a − 1` *are* units), so the maximal-generality statement
handles both cases.

Generality dimensions where the literature varies:
- **conductor**: prime-power `p^n` (the file) ⊂ any `n` (the full standard form). Different generators in the composite case.
- **ambient**: *abstract* `O_K^×` (the universal literature choice) vs. *embedded in `ℂ_[p]`* (the file's RJW "everything inside `ℂ_p`" convention).
- **field of definition**: cyclotomic over `ℚ` (standard) vs. relative cyclotomic extensions (some Iwasawa-theory texts, e.g. function-field analogues).

Disagreement with the literature: **none mathematically.** The project's definition
is the standard one specialised to prime-power conductor and re-presented inside
`ℂ_[p]`.

Proposed restatement (the literature-standard / mathlib-idiomatic target):

```lean
-- For a primitive n-th root of unity ζ in the ring of integers of K = ℚ(ζ_n):
-- the cyclotomic units as a subgroup of (𝓞 K)ˣ
def cyclotomicUnits (K : Type*) [Field K] [NumberField K] {n : ℕ} {ζ : 𝓞 K}
    (hζ : IsPrimitiveRoot (ζ : K) n) : Subgroup (𝓞 K)ˣ :=
  Subgroup.closure { u : (𝓞 K)ˣ | (u : 𝓞 K) = ζ ∨ (u : 𝓞 K) = -ζ ∨
    ∃ a, 1 ≤ a ∧ a ≤ n - 1 ∧ IsUnit ((ζ : 𝓞 K) ^ a - 1) ∧ (u : 𝓞 K) = ... }
  -- composite-n vs prime-power-n branching needed for the generators
```

Cost of restatement: **EXPENSIVE** — the prime-power vs composite generator split
is real mathematics, and the abstract form forces a careful "which products are
units" treatment that the `ℂ_[p]`-embedded prime-power form sidesteps. Per the
skill, **EXPENSIVE does not downgrade the verdict** — but it does feed a genuine
"is the general form worth building now?" question (Phase 7, Q3).

Because Phase 4b is **STRICTLY NARROWER**, Phase 7 considers
`YES-but-generalise-first` prominently (the general form is a real gap — Phase 5

Modern idiom available: **yes** — the mathlib-idiomatic form is the **abstract,
any-conductor `Subgroup (𝓞 K)ˣ`** built from `Subgroup.closure` of the cyclotomic
generators intersected with the (already-mathlib) `(𝓞 K)ˣ`, parametrised by
`[NumberField K]` + `IsPrimitiveRoot`. Crucially — and unlike the `globalUnits`
case — this idiomatic form **does not yet exist in mathlib** (Phase 5: mathlib has
*no* cyclotomic-units group object). So the modern-idiom finding **supports
`YES-but-generalise-first`**, not NO.

- Cost: **EXPENSIVE** (the prime-power/composite generator split; bridging the
  `ℂ_[p]`-embedded prime-power proofs to the abstract any-conductor form).
- Mathlib downstream this enables: a canonical home for the *existing* per-element

## Verdict: `cycloUnits` (Phase 7)

**Category:** `BORDERLINE-needs-human`

**Evidence:**
- Literature search (Phase 3): the concept is the **cyclotomic-unit group** `𝒟_n`
  (Washington `C_n`), fully standard — "the intersection of the full unit group with
  the subgroup generated by the cyclotomic numbers" (Washington Ch. 8 / PlanetMath),
  generated at prime-power level by `±ξ` and `(ξ^a−1)/(ξ−1)` (Wikipedia, verbatim).
  The project def is a faithful transcription; the source is RJW (arXiv:2309.15692).
- Generality analysis (Phase 4): **STRICTLY NARROWER THAN STANDARD** (prime-power
  conductor; embedded in `ℂ_[p]`). The idiomatic abstract any-conductor
  `Subgroup (𝓞 K)ˣ` form (Phase 4c) is a real improvement — and is **not** in mathlib.
  Restatement cost: **EXPENSIVE**.
- Mathlib search (Phase 5): **not in mathlib** under either form. Mathlib has the
  per-element associatedness API (`CyclotomicUnits.lean`, 0 defs) and `(𝓞 K)ˣ`, but
  **no group of cyclotomic units**. (This is the decisive contrast with `globalUnits`,
  which *is* `NO-mathlib-has-it`.)
- Composition check (Phase 6): **NOT-COMPOSABLE** from mathlib (the def's arguments
  are project-local; the abstract form is a real multi-step `def`). Call sites:
  **K = 0** cross-project consumers; load-bearing only inside this one development.

**Rationale.**
Two facts pull in opposite directions, and resolving them is a judgment call the
skill should not make alone — hence BORDERLINE.

*Pulling toward YES-but-generalise-first*: the cyclotomic-units **group** is a
textbook object (Washington devotes Ch. 8 to it; it carries the famous index
theorem `h_n^+ = [E_n : C_n]`), and mathlib genuinely lacks it — mathlib's
`CyclotomicUnits.lean` proves facts about individual `ζ^a − 1` with **no group to
hang them on**. A `NumberField.cyclotomicUnits : Subgroup (𝓞 K)ˣ` would be the
natural home for those facts and the target of the index/class-number theorems,
composing with `Subgroup.index` and the existing `(𝓞 K)ˣ` regulator API. By the
Bourbaki-2.0 rule (Phase 4c), "the literature has the lemmas but not the bundled
group" is exactly the kind of gap mathlib wants filled, and EXPENSIVE does not
downgrade that.

*Pulling away from a clean YES*: the project's actual declaration is **three steps
removed** from that contributable object — (1) prime-power conductor only, (2)
embedded in `ℂ_[p]ˣ` rather than abstract `(𝓞 K)ˣ`, (3) built on two project-local
defs (`cycloGenSet`, `globalUnits`, the latter itself a `NO-mathlib-has-it`
re-presentation of `(𝓞 K)ˣ`). It has **zero** consumers outside this single
development. So the *thing to upstream* is not `cycloUnits` as written but a new,
generalised, abstract def that must be **built and re-proved from scratch
(EXPENSIVE)** against mathlib's `(𝓞 K)ˣ` + `IsPrimitiveRoot` API — and whether
mathlib wants a bundled cyclotomic-units group *at all* (vs. continuing with the
per-element associatedness style its maintainers chose in 2021) is a live
taste/policy question, not something Phases 3–6 settle. The EXPENSIVE-cost +
generality-vs-effort tradeoff is, per the skill's own rule, a BORDERLINE question
to the user rather than a self-resolving downgrade.

So: the bucket is **BORDERLINE between `YES-but-generalise-first` (build the
